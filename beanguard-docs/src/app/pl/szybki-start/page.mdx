# Szybki start

Najszybszy sposób, aby zobaczyć BeanGuard w akcji: trzy kontenery Docker — serwer, panel admina i sklep — plus baza PostgreSQL. {{ className: 'lead' }}

<Note>
  Obrazy `mszajner/beanguard-*` są placeholderem — projekt nie jest jeszcze
  opublikowany na Docker Hub. Zobacz [Pobierz BeanGuard](/pl/pobierz) po aktualne
  nazwy i tagi obrazów, gdy będą gotowe.
</Note>

## Docker Compose {{ id: 'compose' }}

Utwórz plik `docker-compose.yml`:

```yaml
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: beanguard
      POSTGRES_USER: beanguard
      POSTGRES_PASSWORD: beanguard
    volumes:
      - beanguard-db:/var/lib/postgresql/data

  server:
    image: mszajner/beanguard-server:0.1.0
    depends_on:
      - postgres
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres/beanguard
      SPRING_DATASOURCE_USERNAME: beanguard
      SPRING_DATASOURCE_PASSWORD: beanguard
      BEANGUARD_ADMIN_URL: http://localhost:8002
      BEANGUARD_SHOP_URL: http://localhost:8001
    ports:
      - '8000:80'

  admin:
    image: mszajner/beanguard-admin:0.1.0
    depends_on:
      - server
    environment:
      BEANGUARD_SERVER_URL: http://server:80
    ports:
      - '8002:80'

  shop:
    image: mszajner/beanguard-shop:0.1.0
    depends_on:
      - server
    environment:
      BEANGUARD_SERVER_URL: http://server:80
    ports:
      - '8001:80'

volumes:
  beanguard-db:
```

Uruchom całość:

```bash
docker compose up -d
```

Serwer nasłuchuje na `localhost:8000`, panel admina na `localhost:8002`, sklep na `localhost:8001`.

## Pierwsze uruchomienie {{ id: 'start' }}

Przy starcie serwer sam nakłada migracje bazy (Liquibase), tworzy domyślne parametry konfiguracyjne **i od razu generuje klucze RSA/AES** do podpisywania licencji oraz sesji administratorów — nie trzeba tego robić ręcznie. Wejdź na `http://localhost:8002` i zaloguj się do panelu admina.

<Note>
  Domyślne dane logowania administratora znajdziesz w logach kontenera `server`
  przy pierwszym uruchomieniu: `docker compose logs server | grep -i admin`.
</Note>

Zobacz [Panel admina](/pl/panel-admina) po przegląd całego menu.

## Klucze licencji {{ id: 'klucze' }}

Klucz publiczny i sekret AES, które podasz w [konfiguracji klienta](/pl/klient), już czekają na Ciebie — serwer wygenerował je automatycznie przy pierwszym starcie:

1. W panelu admina otwórz **[Klucze kryptograficzne](/pl/panel-admina/klucze-kryptograficzne)**, zakładka **Licencje**.
2. Przyciskiem **Kopiuj** skopiuj **klucz publiczny** i **klucz szyfrowania (AES)**.
3. Wklej je do `ServerConfig` w implementacji `BeanGuardConfiguration` swojej aplikacji.

<Note>
  Nie klikaj tu **Generuj nowe klucze** przy pierwszej konfiguracji — ten
  przycisk służy do rotacji i natychmiast unieważnia już wydane licencje.
  Klucze wygenerowane automatycznie przy starcie serwera są gotowe do użycia.
</Note>

## Co dalej {{ id: 'dalej' }}

- Skonfiguruj [Branding](/pl/panel-admina/branding) i [Ustawienia](/pl/panel-admina/ustawienia), żeby maile, panel i certyfikaty pokazywały Twoje dane zamiast domyślnych.
- Dodaj pierwszy [produkt](/pl/panel-admina/produkty) do sprzedaży albo od razu ręczną [licencję](/pl/panel-admina/licencje) dla klienta testowego.
- Zintegruj [beanguard-client](/pl/klient) z własną aplikacją.
- Skonfiguruj [sklep](/pl/sklep), żeby klienci mogli kupować licencje samodzielnie.
